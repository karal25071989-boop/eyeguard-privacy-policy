1. Who operates EyeGuard

EyeGuard Developer provides EyeGuard, a parent-operated Android app for a family device. A parent creates a Parent PIN, chooses Parent Mode or Child Mode, and turns protections on or off. The parent may also activate Parent Freedom Mode, described below.

EyeGuard does not ask a child to create an EyeGuard account. EyeGuard does not operate an EyeGuard user account, advertising network, or analytics service in the current application.

Parent Freedom Mode

Parent Freedom Mode is an optional operating mode intended for parent use. It does not replace Child Mode, and it does not turn off every EyeGuard protection or every EyeGuard PIN prompt.

  • Authentication: The parent must confirm using the Parent PIN or fingerprint before Parent Freedom Mode turns on.
  • Android Settings: During normal use, Android Settings can open without repeated EyeGuard PIN prompts.
  • User identification: The "Who Is Using This Phone?" prompt is not shown while Parent Freedom Mode is active.
  • Break reminders: Existing Parent Mode break reminders remain active.
  • Website filtering: Parent Freedom Mode uses the same VPN Safe Browsing behavior as Normal Parent Mode. EyeGuard's local website filter runs when Child Mode is active and stops in Normal Parent Mode and Parent Freedom Mode.
  • Mode persistence: Parent Freedom Mode remains active after screen lock, screen unlock and device restart until the parent changes modes.
  • Pause EyeGuard: Settings Lock continues to apply while EyeGuard is paused.
  • Child protection: Child Mode protections remain unchanged. Parents should switch to Child Mode before handing the device to a child.

Parent Freedom Mode does not guarantee compatibility with every financial or banking application.

2. What stays on the device

The following are processed or stored on the phone. They are not uploaded to an EyeGuard server.

Parent PIN and recovery. The PIN and the recovery answer are stored only as salted PBKDF2 hashes (12,000 iterations, HMAC-SHA256 with an HMAC-SHA1 fallback) in the private preferences file eyeguard_guardian. The PIN itself is not stored. That file is excluded from Android backup.

Fingerprint. When a parent turns fingerprint unlock on, Android performs the match. EyeGuard stores an on/off preference in eyeguard_biometric and a key in the Android Keystore (eyeguard_biometric_gate_v1). EyeGuard does not receive or store a fingerprint image. The on/off preference file is not in the current backup exclude list. The Keystore key is not part of ordinary Auto Backup.

Protection settings. Parent Mode, Child Mode, Parent Freedom Mode, Eye Lens strength and mode, break settings, blink and distance settings, App Lock selections, and parent website allow or block choices stay in the app's private storage.

Parent Freedom Mode activation status and whether its first-use notice has been displayed are stored in eyeguard_guardian as guardian_parent_freedom_active and guardian_parent_freedom_intro_seen.

The guardian, lens-preference, website-control, network-filter, app-lock, and recent-install preference files are excluded from Android backup.

Pause timer. A pause deadline can be stored in eyeguard_pause. That file is not in the current backup exclude list.

Other local preferences. Battery-readiness, lens-off reminder, and Edge Button position files (eyeguard_battery_readiness, eyeguard_lens_off_reminder, eyeguard_edge_tab) are also not in the current backup exclude list. They are settings, not an account profile.

Usage Access. If the parent grants Usage Access, EyeGuard reads Android usage statistics on the device to time breaks and to show a usage report. Those statistics are not uploaded by EyeGuard.

Installed apps. EyeGuard reads launchable apps to build the App Lock list and a recent-install list for the parent. It does not use QUERY_ALL_PACKAGES. Those lists stay on the device. If the parent chooses to uninstall another app, EyeGuard opens Android's own uninstall screen.

Eye Lens and other on-screen windows. The colour tint, Edge Button, blink reminders, distance warnings, and parent break reminders are drawn on the device. Child Break and the child-protection hurdle use a separate Display over other apps window, also on the device.

Website names while filtering. While the local filter is running, EyeGuard inspects DNS names and TLS server names in memory to allow or block a site. The filter path does not save those names as a browsing history. EyeGuard does not decrypt HTTPS page contents.

Diagnostic files. The app can write local diagnostic logs on the device. The live domain-trace log path is enabled only when BuildConfig.DEBUG is true. Debug builds may also record local mode synchronization diagnostics without PINs or biometric information. These files are not sent to an analytics service.

3. What leaves the device

EyeGuard does transmit some network data. It does not send that data to an EyeGuard account server.

DNS lookups. While website filtering is on, the local VPN is configured with the public resolvers 1.1.1.1 and 8.8.8.8 (NetworkFilterVpnService.kt). Domain names in DNS lookups are sent to those resolvers so a site can be allowed or blocked.

This is ordinary DNS, not an encrypted DNS connection in the current code. EyeGuard does not receive a copy of those lookups on its own server. Allowed traffic then continues to the website over the phone's own network. EyeGuard is not a remote VPN provider and does not offer anonymity or a change of location.

Website-protection list. EyeGuard downloads a signed list of site names over HTTPS from:

https://karal25071989-boop.github.io/eyeguard-ota/manifest.json

and from the HTTPS file that manifest names. The request is a download (HTTP GET). It does not include the Parent PIN, a fingerprint, or a browsing history. The phone's IP address is visible to that host as part of a normal HTTPS connection.

The list is checked with a public signature key on the device before use. The private signing key is not in the app.

Play Store link. If the parent uses Share or Rate, Android or the Play Store app opens a Play Store URL for this package. That is the store's own page, not an EyeGuard analytics call.

No advertising identifier and no analytics SDK are included in the current Gradle dependencies.

4. Accessibility

If the parent agrees in EyeGuard and then turns the service on in Android settings, EyeGuard uses an Accessibility service to draw Eye Lens, the Edge Button, blink reminders, distance warnings, and parent break reminders over other apps.

The service is not a disability-support tool (isAccessibilityTool is false). It is not designed to read screen contents, read what is typed, perform gestures, or take screenshots. The running service does not request accessibility events.

The parent can turn the service off in Android Accessibility settings. Features that depend on it stop when it is off.

Display over other apps remains a separate permission, used for Child Break and related protection windows, and also checked by the Eye Lens path.

5. VPN and website filtering

If the parent allows Android's VPN consent while Child Mode needs website protection, EyeGuard starts a local VPN on the device. The tunnel address is on the phone. There is no remote EyeGuard VPN server. The purpose is to filter restricted websites, not to hide identity or bypass blocks.

Some financial apps may warn or limit access while this VPN is active. Turning Child Mode off, which requires the Parent PIN, stops that protection mode.

Parent Freedom Mode uses the same website-filtering behavior as Normal Parent Mode. The local VPN is not started by Parent Freedom Mode. The financial-app warning above applies while the local VPN is active.

6. App Lock and Device Administrator

App Lock. The parent can require the Parent PIN before selected apps, including Settings, open. Those choices stay on the device. Selected-app App Lock restrictions apply in Child Mode under the existing protection settings.

While Parent Freedom Mode is active, Android Settings can open without a repeated EyeGuard Parent PIN, except while EyeGuard is paused. Other EyeGuard PIN prompts are not all removed.

Protect EyeGuard. If the parent turns this on, EyeGuard shows an explanation, asks for the Parent PIN, and then opens Android's Device Administrator screen.

The admin declaration requests no password, wipe, camera, or other device-admin policy. Android can still refuse to uninstall EyeGuard until that admin is deactivated.

The parent turns it off in EyeGuard with the Parent PIN, which asks Android to remove the admin. EyeGuard does not use device-owner uninstall blocking.

7. How long information stays, and how to delete it

Local settings and hashes remain until the parent changes them, clears EyeGuard's storage, or uninstalls the app.

Clearing storage removes the local PIN hash, recovery hash, and settings. Uninstall can require the parent to turn off Protect EyeGuard first, because Android Device Administrator is active.

EyeGuard has no server account to delete. DNS lookups are not stored by EyeGuard as a history.

Copies of non-excluded preference files that Android Backup has already saved follow the user's Google account backup rules, which EyeGuard does not control. The publisher should decide whether preference files that are not excluded today should be excluded before release.

The downloaded site list stays on the device until a newer signed list replaces it or the app's files are removed.

8. Children

A parent operates EyeGuard. A child may use the phone while Child Mode is on. EyeGuard does not ask the child for a name, email address, or EyeGuard account.

Parent Freedom Mode is intended for parent use and does not replace Child Mode. Parents should activate Child Mode before allowing a child to use the device.

Website filtering, breaks, and the screen tint run for that family device. Domain names looked up while filtering is on are sent to the DNS resolvers in section 3.

That is the transmission a parent should understand before turning filtering on. It is not a profile sold by EyeGuard.

EyeGuard is designed for parents and guardians to manage protection settings on their devices. The app's participation in the Google Play Designed for Families program, if applicable, is determined separately through Google Play Console.
